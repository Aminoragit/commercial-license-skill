# 적대적 검토 및 자가 개선 기록

검토일: **2026-10-29** · 대상: 로컬 **0.4.0 개발 버전** · 방식: 결함 재현 → 수정 → 회귀 검증을 네 차례 수행.

초기 상태의 테스트 9개는 통과했다. 그러나 그 테스트만으로는 중첩 라이선스 표현식, 사용자 지정 조건, 충돌 근거, 플랫폼별 동작을 검증할 수 없었다. 아래 기록은 로컬 코드와 문서에 대한 검토이며 외부 법률 검토나 모든 LLM 플랫폼의 실사용 인증이 아니다. 자동 테스트의 수를 법적 신뢰도 점수로 환산하지 않았다.

## 1회 — 라이선스 판정에 대한 공격

**반례:** `(MIT OR Apache-2.0) AND GPL-3.0-only`를 기존 구현이 `allow`로 판정했다. 괄호를 먼저 제거하고 OR 문자열을 나누어 누적 GPL 조건을 잃었다. `MIT WITH invented-exception`도 MIT라는 이유로 허용했다.

**평가:** 출시 차단 수준의 거짓 허용이다. 상업 사용 가능 여부와 비공개 배포 조건을 혼동하는 문서까지 있어 결과를 그대로 채택하기 어려웠다.

**수정:** 길이·토큰 수를 제한한 재귀 하강 파서를 적용해 `WITH > AND > OR`와 괄호를 보존했다. 예외·잘못된 표현식·관계가 불명확한 레거시 배열은 자동 허용하지 않는다. 허용 목록이 주어지면 그 목록에 맞는 완전한 분기 안에서 선택한 이용 허락을 기록한다.

**검증:** `node --test test/policy.test.mjs`의 3개 테스트가 통과했다. 여러 중첩·우선순위·오류 표현식과 사용자 지정 분기를 각 테스트 안에서 대조했다. 라이선스 식별자 전체 목록의 유효성 검사나 법적 호환성 증명은 구현 범위가 아니다.

## 2회 — 수집 근거와 누락에 대한 공격

**반례:** 잠금 파일만 있는 직접 의존성이 요청 범위 버전으로 남거나 전이 항목과 중복됐다. dev 전이 의존성이 런타임처럼 포함될 수 있었다. 설치본 MIT와 잠금 파일 GPL이 충돌해도 먼저 읽은 값이 남았다. Python `License-Expression`을 읽지 않았고 Cargo CRLF 블록을 놓쳤다. 손상된 JSON은 빈 데이터로 처리됐다.

**평가:** 근거와 범위가 불안정해 허용·위험 양쪽의 오판 가능성이 있었다. 설치 패키지 아래 예제의 `package.json`도 실제 패키지처럼 수집될 수 있었다.

**수정:** 잠금 버전과 dev/optional 범위를 반영하고 설치된 패키지 경로를 제한했다. 선언 근거를 보존하며 충돌 시 이용 허락을 자동 선택하지 않는다. 알려진 더 높은 위험은 유지한다. Python 표현식 우선순위와 CRLF를 수정했다. 미확인 vendor 문구도 항목으로 남기고 JSON 오류는 명시적으로 실패시킨다.

**검증:** `node --test test/inventory.test.mjs test/policy.test.mjs test/scan.test.mjs`의 13개 테스트가 통과했다. 인벤토리 테스트는 격리된 임시 디렉터리에 입력을 만들고 종료 시 정리한다. 지원하지 않는 잠금 파일·워크스페이스·최종 바이너리까지 검사했다고 주장하지 않는다.

## 3회 — 사용자 조건과 대체 추천에 대한 공격

**반례:** 기존 `profile`은 보고서 이름만 바꾸고 판정에는 반영되지 않았다. MIT만 원하는 요청을 적용할 방법이 없었다. FFmpeg의 동영상 작업에 이미지 처리기, 데이터베이스에 클라이언트 패키지를 제시했다. 테스트용 가상 패키지를 실사용 추천처럼 노출했다. MCP 스키마는 적혀 있어도 실제 타입을 검증하지 않았다.

**평가:** 사용자가 요청한 핵심인 ‘원하는 조건에 맞는 실용적인 대체재’를 충족하지 못했다. 메타데이터 검색 결과를 검증한 추천과 구분해야 했다.

**수정:** `allowedLicenses`를 CLI·스캔·프로젝트 설정·후보 필터·MCP에 연결했다. 미지원 profile은 오류로 처리한다. 부적절한 후보와 가상 추천을 제거하고 `unverified`·`metadata-only`를 구분했다. 원본 패키지는 온라인 대체 후보에서 제외한다. MCP는 필수 인자·타입·범위를 검사한다. 온라인 결과는 통제된 메타데이터 응답으로 검증한다.

**검증:** 추천/MCP의 7개 테스트가 통과했고, 앞선 테스트와 합쳐 20개가 통과했다. 실제 후보의 모든 버전·전이 의존성·유지보수·API 적합성을 검증한 결과라는 주장은 하지 않는다. 해당 조사는 스킬의 후속 근거 확인 단계다.

## 4회 — 설치·호스트·문서와 실제 실행에 대한 공격

**반례:** 백업에 실패하면 기존 편집본을 삭제할 수 있었다. 공유 설치 경로를 여러 번 덮어쓸 수 있었고, 소스 스킬 자체를 대상으로 설치·제거할 수 있었다. CLI 기본값이 설정 파일의 개인정보 가림·dev 범위를 덮어썼다. 잘못된 실패 임계값이 조용히 넘어갔다. MCP 문서는 실제 `path` 인자 대신 `root`를 사용했다. 평가 자료는 존재하지 않는 fixture를 참조했다. README는 법적 결과와 생태계 지원을 과장했고 언어 링크가 과거 커밋에 고정돼 있었다.

**평가:** 기능 수정만으로는 부족했다. 사용자가 문서대로 실행했을 때 새 동작을 재현하고, 자신의 편집본과 민감한 소스 구문을 보존할 수 있어야 했다.

**수정:** agy CLI 어댑터, 공유 경로 중복 제거, 백업 실패 시 중단, 복사 실패 시 기존 백업 복구, 소스 디렉터리 보호를 적용했다. CLI 옵션·설정 우선순위와 잘못된 입력을 검증한다. MCP 루트는 정규화된 실제 경로로 확인한다. 스킬을 공급된 자료만으로도 동작하도록 정비하고, 자산·모델·가중치·데이터셋·프롬프트 주입·클린룸 경계를 포함했다. 영문/한국어 README를 새 이미지 2장과 함께 재작성하고 미배포 버전은 로컬 명령으로 재현하도록 했다. 마지막 재검토에서 발견한 잠금 파일 없는 설치형 dev 의존성의 범위 상승도 수정했다. 범용 테스트 자동 탐색이 합성 fixture 소스까지 실행하는 문제는 명시적 테스트 파일 목록을 사용하는 플랫폼 독립 실행기로 해결했다. 스킬 검증기가 허용하지 않는 `compatibility` 키는 `metadata.requirements`로 옮겼다.

**검증:** 전체 `npm test`, 로컬 문서 링크·평가 fixture 검사, 스킬 구조 검증, npm 패키지 구성 검사, 실제 stdio 서버 왕복 호출 및 README 시각 검토를 실행한다. 최종 실행 결과는 아래에 기록한다. 호스트별 계정·실제 앱 자동 로딩까지 확인한 것은 아니다.

## 최종 검증 결과

실행 환경: Windows · Node.js **v24.21.0** · Python **3.15.0**. CI의 다른 Node 버전이나 실제 호스트 계정 환경까지 이번 로컬 실행으로 검증한 것은 아니다.

- 자동 회귀 테스트: `npm test` **33개 통과**. 파서·인벤토리·후보 필터·CLI·MCP·설치 백업 실패와 복구를 포함한다.
- 문서 링크·fixture 경로: `npm run docs:check` 통과. 15개 Markdown과 55개 로컬 링크, 수동 평가의 fixture 경로를 확인했다.
- 스킬 구조: 제공된 `quick_validate.py`에서 **Skill is valid!** 확인. 구조 검사는 에이전트의 판단 능력을 증명하지 않는다.
- npm 패키지 구성: `npm pack --dry-run` 및 실제 `npm pack` 통과. 33개 파일, 압축 약 4.4 MB. tarball을 별도 폴더에 추출해 버전 조회·정책 스캔·소스 가림·스킬 설치·공유 경로 처리를 확인했다. 새 README 이미지와 참조 문서는 포함되고 테스트 fixture는 제외됐다. 이전 README 이미지 두 장은 저장소에 보존하되 npm 배포 목록에서 제외했다.
- MCP 실제 stdio: 자식 프로세스로 초기화 → 도구 목록 → 정책 적용 스캔 → 소스 구문 가림을 왕복 검증했다. 정규화된 경로 검사는 외부 경로를 가리키는 링크도 거부했다.
- 영문·한국어 README 렌더링: 로컬 Markdown HTML 미리보기를 Edge headless로 **1440px 밝은 화면·390px 모바일·1440px 어두운 화면**에서 각각 검사했다. 6개 조합 모두 이미지 깨짐과 페이지 가로 넘침이 없었다. 데스크톱·모바일·본문 이미지 배치를 시각적으로 확인했다. GitHub 실제 서비스의 렌더러와 동일하다는 주장은 하지 않는다.

## 남은 범위와 판단

- 로컬 검사는 부분 인벤토리다. pnpm·Yarn·uv·Poetry 잠금 파일, 중첩 워크스페이스, 모든 빌드 산출물·OS 패키지·저작물은 자동 해결하지 않는다.
- 카탈로그·npm 검색은 후보 탐색이다. 정확한 버전의 라이선스 원문, 중요한 전이·네이티브 항목과 사용 API가 확인돼야 채택을 권고할 수 있다.
- 예외·사용자 정의 이용 허락·구매 권한·결합물 판단은 정확한 문구와 사실관계가 필요하다. 법률 전문가의 검토를 대신하지 않는다.
- 파일 시스템 어댑터 테스트는 모든 ChatGPT·Codex·agy·Gemini·Claude 세션의 기능·권한·자동 실행을 보장하지 않는다.
- 에이전트 평가 시나리오는 수동 평가용이다. 이번 작업에서 모든 외부 모델을 호출해 통과시킨 것으로 표시하지 않는다.

냉정한 결론: 초기의 잘못된 허용과 요청 조건 누락은 회귀 테스트를 갖춘 구현으로 수정했다. 실사용 가능한 검토 도구로 개선했지만, 라이선스 적합성을 자동으로 완벽히 보장한다는 주장은 근거가 없다.
