# Review report template

Adapt the depth to the request; keep unresolved items visible.

## Conditions and coverage

Accepted/excluded licenses, commercial/source-sharing requirements, deployment and modification assumptions, reviewed files/artifacts, scan/tool version, offline/online mode, review date, excluded scopes and unsupported formats. State whether the CLI ran or the review used supplied material only.

## Findings

| Component and exact version | Observed license / chosen grant | Primary evidence and date | Usage / deployment | Policy result and obligations | Unknowns / action |
|---|---|---|---|---|---|

Keep facts separate from interpretation. `allow` is metadata triage, not a waiver of notices or a legal guarantee.

## Alternatives for each blocker

| Candidate and exact version | License evidence and verification status | Required feature coverage / gaps | Transitive and native risks | Maintenance evidence | Migration work / tests | Recommendation |
|---|---|---|---|---|---|---|

Rank license fit before feature and migration preferences. Include one, two or no candidates according to available evidence. Explain when a keep-and-comply path is feasible. Cite exact artifact paths or upstream versioned URLs; do not cite only a search snippet.

## Follow-through

Concrete notices, changes, test results actually observed, unresolved release questions and the next action. If legal review is needed, name the precise trigger and uncertainty. Never claim a compliance certificate or exhaustive coverage.
